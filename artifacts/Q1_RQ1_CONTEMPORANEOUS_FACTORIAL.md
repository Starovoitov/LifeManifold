## 1. Question and scope

On independently generated warm-start archives, estimate the effects of:

1. parent-level scalar bundle: fixed placeholders vs live `(fitness, uncertainty)`;
2. target policy: `min_fitness_frontier` vs `uniform_frontier`;
3. their interaction.

The treatment is the tested two-field scalar bundle. A separate shuffled-pair
placebo tests information alignment; it is not folded into the 2×2 interaction.

## 2. Frozen design

### 2.1 Blocks and sample size

- **5 independent warm-start archives**, generated by the no-LLM nightly
  baseline process with source seeds `41001`–`41005`.
- Each floor is truncated at the first prefix reaching exactly **971 occupied
  cells / 38.84% coverage** after strict-`>` collapse.
- **2 continuation RNG replicates per archive**, giving 10 paired continuation
  blocks. Continuation seeds are assigned by the checked-in plan generator.
- Arms are run in a deterministic randomized order within each
  archive×continuation block.

The archive, not the continuation seed, is the outer generalization unit.
Inference must therefore resample/cluster by archive.

### 2.2 Primary 2×2 arms

| Arm | Scalar bundle | Target policy |
|---|---|---|
| `stub_minfit` | constants `(0.5, 1.0)` | `min_fitness_frontier` |
| `live_minfit` | frozen-MLP live pair | `min_fitness_frontier` |
| `stub_uniform` | constants `(0.5, 1.0)` | `uniform_frontier` |
| `live_uniform` | frozen-MLP live pair | `uniform_frontier` |

All other scheduler settings are identical: 650×50 proposal slots, 20 random
+ 20 genetic + 10 LLM slots per batch, no acquisition skipping, the same
checkpoint, simulator, prompts, and archive resolution.

### 2.3 Desirable placebo arm

`shuffled_uniform` uses the same multiset of live `(fitness, uncertainty)` pairs
as `live_uniform`, permuted across the ten LLM slots within each batch. This is
the distribution-matched aligned-vs-shuffled comparison.

### 2.4 Immutable LLM treatment

- Request model: `gpt-4o-mini-2024-07-18`.
- Endpoint and sampling settings are pinned in
  `worldspace/specs/llm_world_generator_rq1_fixed_openai.yaml`.
- Every request, response, retry, error, usage record, response model,
  system fingerprint, finish reason, parser outcome, and fallback is archived.
- Every LLM call has a stable `llm_call_id` joined to its evaluated proposal.
- All evaluated proposals from **all emitter types** are logged.

OpenAI's `seed` is a best-effort decoding control, not a guarantee of identical
outputs. The response model and system fingerprint remain mandatory audit
fields. A clean git commit and exact model availability are launch blockers.

## 3. Endpoints and estimands

Primary endpoint:

- terminal **new coverage above the 971-niche floor**, in percentage points.

Companions:

- terminal total coverage;
- terminal QD-score;
- occupied-bin mean fitness (denominator caveat retained).

Primary contrasts, computed within every archive×continuation block:

1. scalar effect at minfit: `live_minfit - stub_minfit`;
2. scalar effect at uniform: `live_uniform - stub_uniform`;
3. policy effect under stub: `stub_uniform - stub_minfit`;
4. policy effect under live: `live_uniform - live_minfit`;
5. interaction:
   `(live_uniform - stub_uniform) - (live_minfit - stub_minfit)`.

Placebo contrast:

6. alignment effect: `live_uniform - shuffled_uniform`.

Report means and archive-clustered bootstrap **95% CIs**, all raw block deltas,
paired correlations, and an unpaired sensitivity. No equivalence claim, TOST,
Holm family, or “0 pp” wording is authorized by this lock.

## 4. Mechanism/audit outputs

Per arm, archive, continuation, and emitter type:

- number and distribution of target cells;
- unique targets, normalized entropy, maximum target share, repeat rate;
- fill, improve, reject, and early-extinction rates;
- target-to-realized-bin error;
- LLM validity, fallback, retry, timeout, and parser-outcome rates;
- parent→child rule Hamming distance and continuous-scalar edit magnitude;
- live-vs-prompt scalar alignment (including shuffled placebo);
- completeness join between `llm_call_log.jsonl` and `proposal_log.jsonl`.

## 6. Operator commands (how this matrix was run)

Read-only plan and preflight:

```bash
uv run python scripts/run_rq1_contemporaneous_factorial.py plan
uv run python scripts/run_rq1_contemporaneous_factorial.py preflight
```

After committing/pinning this package, generate each independent CPU-only floor
source and materialize its 971-cell prefix:

```bash
uv run python scripts/run_rq1_contemporaneous_factorial.py \
  run-floor-source --archive-index 0 --execute --ack RQ1-CF-2026-08-13
# repeat archive-index 1..4
```

The command above is intentionally guarded. Floors, plan, probe, and the 50-arm
matrix were executed after that lock; analysis commands at the bottom of this
section are the post-matrix readout. Before live LLM runs, write the immutable
plan from the clean commit and perform the separately authorized one-call
dated-model probe:

```bash
uv run python scripts/run_rq1_contemporaneous_factorial.py plan \
  --write artifacts/experiments/q1-rq1-contemporaneous/experiment_plan.json
uv run python scripts/run_rq1_contemporaneous_factorial.py \
  probe-model --execute --ack RQ1-CF-2026-08-13
uv run python scripts/run_rq1_contemporaneous_factorial.py preflight
```

Only after preflight reports `ready_for_live_execution: true`, start explicitly
acknowledged workers:

```bash
RQ1_FACTORIAL_EXECUTE=YES RQ1_FACTORIAL_WORKERS=2 \
  ./scripts/run_rq1_factorial_worker.sh 0
RQ1_FACTORIAL_EXECUTE=YES RQ1_FACTORIAL_WORKERS=2 \
  ./scripts/run_rq1_factorial_worker.sh 1
```
